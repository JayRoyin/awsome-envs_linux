## 问题描述

Linux 设备时间异常时，常见现象包括：

- 系统时间重启后又回到 `1970-01-01`
- `apt`、`wget`、`curl`、浏览器或其他 HTTPS 工具出现证书校验失败
- NTP 服务未正常工作，系统时间无法自动同步

这类问题在没有 RTC 电池、长时间断电、镜像精简过系统服务，或者 `systemd-timesyncd` 被屏蔽的设备上比较常见。

## 问题原因

排查下来，通常有以下几个关键原因：

### 1. 时间同步服务被屏蔽

如果 `systemd-timesyncd` 被 `mask`，系统就无法正常启动时间同步服务。

### 2. 系统时间偏差过大

当系统时间严重错误时，很多 HTTPS 请求会因为证书的生效时间或过期时间校验失败而报错。  
这时候先手动把时间拉回到“当前年份附近”，就能先打破证书报错的死循环。

### 3. 硬件时钟没有同步

如果只修正了系统时间，没有把当前时间写回硬件时钟，那么设备重启后仍然可能回到错误时间。

## 解决方案

### 步骤 1：先解除时间服务屏蔽（关键）

```bash
sudo systemctl unmask systemd-timesyncd
sudo systemctl enable systemd-timesyncd
```

这一步的目的是恢复 `systemd-timesyncd` 的可用状态，并设置为开机自动启动。

### 步骤 2：手动设置一个正确的大概时间（打破证书死循环）

```bash
sudo date -s "2025-12-25 12:00:00"
```

说明：

- 这个时间不需要完全精确，只要大致接近当前真实时间即可
- 上面只是一个示例时间
- 如果你执行时的实际日期已经是 `2026-04-20` 或更晚，建议直接改成接近当前日期的时间，而不是固定写 `2025`

例如当前时间大致在 2026 年，也可以这样设置：

```bash
sudo date -s "2026-04-20 12:00:00"
```

### 步骤 3：启动时间同步，自动校准到精确时间

```bash
sudo systemctl start systemd-timesyncd
sudo timedatectl set-ntp true
```

执行后，系统会尝试通过 NTP 自动将时间校准到准确值。

### 步骤 4：把时间写入硬件，防止重启变回 1970

```bash
sudo hwclock --systohc
```

这一步会把当前系统时间写入硬件时钟，避免重启后再次回到错误时间。

### 步骤 5：最后检查结果

```bash
timedatectl
```

重点关注以下几项是否正常：

- `System clock synchronized: yes`
- `NTP service: active`
- 当前显示的系统时间是否已经正确

### 可选：优化为国内 NTP 服务器

如果默认 NTP 服务器较慢，可以手动改为国内常用源。

编辑配置文件：

```bash
sudo nano /etc/systemd/timesyncd.conf
```

修改为：

```ini
[Time]
NTP=ntp.aliyun.com ntp.tencent.com
FallbackNTP=ntp.ubuntu.com
```

保存后重启服务：

```bash
sudo systemctl restart systemd-timesyncd
```

## 预防措施

1. 确保 `systemd-timesyncd` 未被屏蔽，并保持开机自启
2. 设备首次联网后，优先检查一次 `timedatectl` 状态
3. 如果设备经常断电或没有可靠 RTC，建议定期执行 `sudo hwclock --systohc`
4. 海外默认时间源较慢时，可以提前配置国内 NTP 服务器提高同步成功率

## 相关命令速查

```bash
# 查看当前时间与时区状态
timedatectl

# 查看当前系统时间
date

# 查看硬件时钟
sudo hwclock -r

# 查看时间同步服务状态
systemctl status systemd-timesyncd

# 手动重启时间同步服务
sudo systemctl restart systemd-timesyncd

# 关闭 / 开启 NTP 自动同步
sudo timedatectl set-ntp false
sudo timedatectl set-ntp true
```
